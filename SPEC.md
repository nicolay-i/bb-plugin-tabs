# Спецификация: верхние вкладки чатов

## Цель

Дать быстрый доступ к текущему чату и чатам с текущей работой, включая быстрый переход к закреплённым чатам с root-экрана «Новый чат», не заменяя sidebar BB и не меняя исходный код BB.

## Поведение

1. Список состоит из закреплённых вкладок и не более одной временной preview-вкладки.
   - Просматриваемый сейчас чат занимает единственную preview-вкладку, если он не закреплён. Если открытый чат отсутствует в снимке sidebar, данные восстанавливаются через публичный SDK по ID маршрута; если preview исчезла из plugin-state, она восстанавливается при следующем изменении состояния. Фоновая работа получает preview только когда просматриваемый чат уже закреплён или текущего чата нет; она не скрывает вкладку просматриваемого чата. При переходе в другой незакреплённый чат его preview заменяет прежнюю.
   - Если чат уже закреплён, обновляется только его подпись: он не вытесняет существующую preview.
   - Preview имеет `pinned: false` в plugin-owned состоянии и отображает название чата курсивом.
2. Плагин считает чат активной работой, если sidebar API сообщает хотя бы один из признаков:
   - `hasPendingInteraction`;
   - ненулевые `workflows`, `backgroundAgents`, `backgroundCommands`, `planMode` или `goals`;
   - indicator: `waiting-for-input`, `workflow`, `background-agent`, `background-command`, `plan-mode`, `goal` или `runtime`.
   - Активность дочернего чата сворачивается по всей доступной цепочке `parentThreadId`: каждая вкладка-предок получает рабочую точку. Для автоматического preview выбирается верхний доступный разговор этой цепочки; отсутствующие либо циклические parent-связи безопасно обрываются.
   - Для открытых вкладок и доступных потомков плагин также опрашивает публичный RPC `workflows.workflowActiveRuns`. Поэтому queued/running durable workflow виден даже до обновления sidebar activity; при недоступности `workflows` плагин безопасно остаётся на sidebar state. Sidebar/realtime — приоритетные источники: fallback не делает частый poll, объединяет одинаковые in-flight `tabs_list`, проверяет новое множество дочерних workflow ID только при его материальном изменении, затем revalidate раз в 15 секунд при известной активной durable работе либо раз в 30 секунд в idle. В `document.hidden` таймер остановлен, а возврат в foreground делает один свежий запрос. Идентичный текущему plugin-owned snapshot не вызывает mutation `tabs_sync_activity`; отличающиеся запросы сериализуются до последнего актуального input.
3. Только `isUnread`, `unread-success`, `unread-error` и обычный draft не считаются активной работой. Однако если такой чат уже есть в полосе, `isUnread` показывает отдельную компактную точку и добавляет к доступному имени вкладки «есть непрочитанные сообщения»; точка обновляется из live sidebar state и не заменяет индикатор runtime-работы.
4. Двойной щелчок по preview закрепляет её. Двойной щелчок **по названию** уже закреплённой вкладки открывает inline-редактор: Enter или потеря фокуса сохраняют имя через `experimental_useSidebarThreadActions().rename()`, Escape отменяет даже если затем browser посылает `blur`. В самой полосе нет постоянной pin-кнопки: закрепление доступно в контекстном меню.
5. Верхняя полоса — единая вручную упорядочиваемая горизонтальная последовательность: проект остаётся метаданными для hover-подсказки, но не группирует и не переопределяет позиции вкладок. Закреплённую вкладку можно перетащить в единственную подсвечиваемую щель между закреплёнными вкладками, включая щель через границу проектов; порядок сохраняется в plugin-owned state и синхронизируется между окнами. Сами вкладки не делятся на левую/правую drop-зоны. Preview не перетаскивается, потому что она временная и всегда единственная. Во время drag источник становится полупрозрачным, активная щель отмечается theme-derived линией, а полоса автопрокручивается у краёв. Закреплённые вкладки располагаются перед preview; вложенной вертикальной прокрутки нет. Hover-подсказка tab показывает полное название проекта и чата, не занимая место в полосе.
6. На desktop обычный vertical wheel над полосой с горизонтальным переполнением листает её горизонтально, включая жест над активной кнопкой вкладки. `Ctrl/⌘+wheel` не перехватывается. Единственная нативная horizontal scrollbar имеет theme-derived track/thumb, расположена над вкладками и синхронизирована с их content scroller. Она показывается только когда `scrollWidth > clientWidth`; при отсутствии переполнения rail скрыт, не фокусируется и не занимает высоту полосы.
   - На desktop и compact/mobile рядом со strip показывается одна и та же icon-кнопка списка, когда в меню есть минимум два направления перехода. `showTabListButton` выключает её целиком; `tabListButtonPosition` перемещает её слева направо без изменения ручного порядка чатов и `Ctrl+Tab`; `showTabListPinned` и `showTabListHistory` независимо скрывают соответствующие разделы. Она открывает доступное подменю, а не native `select`: сначала показывает «Закреплённые» в общем ручном порядке, затем отдельную plugin-owned «Историю» по убыванию последнего посещения или обнаруженной рабочей активности. История хранит до 100 уникальных чатов отдельно от `TabsState`, поэтому close/preview не удаляют recent navigation. При обнаружении новой активности каждый рабочий root-чат поднимается в истории, даже если пользователь не переходил в него; повторный снимок с тем же `updatedAt` не создаёт нового посещения, а частые обновления работающего чата ограничены одним подъёмом в истории за 5 секунд. Обновление sidebar без перехода в текущий чат повторно не поднимает его в истории. Пункт меню повторяет root-карточку: title сверху, проект слева во второй строке, а справа — «Работает» и/или «Непрочитанное» с точкой. У спокойного чата нет пустого индикатора, а длинный проект обрезается многоточием. Выбор доступного пункта вызывает `experimental_useSidebarThreadActions().open(threadId)`. Первые 8 history-записей видны сразу; «Ещё» раскрывает следующую локально доступную порцию по click/tap сразу или автоматически после удержания mouse pointer 300 мс на desktop. Перед первой записью каждой догруженной порции остаётся theme-derived `DropdownMenu.Separator`, поэтому граница страницы видна, но не становится keyboard-пунктом. Уход указателя, закрытие меню и unmount отменяют pending таймер. После публичных lifecycle-событий `thread.archived`/`thread.deleted` ID сразу удаляется из `TabsState`, поэтому не виден в strip, pinned-разделе, root-карточках или `Ctrl+Tab`; существующая history-запись остаётся disabled tombstone с зачёркнутым title, label и иконкой архива/удаления. При `thread.unarchived` tombstone снимается, но закрытый pin/preview не восстанавливается автоматически. При startup/reload плагин делает bounded сверку максимум 200 сохранённых ID через публичный `bb.sdk.threads.get()` для событий, случившихся до его загрузки; transient/permission failure не маскируется под удаление. История не изменяет flat ручной порядок pin, preview semantics или основной strip. На compact/mobile справа остаётся горизонтально свайпаемый strip без desktop proxy-scrollbar; touch target кнопки Close остаётся доступным, а HTML drag-and-drop на этой поверхности не предлагается как touch-жест.
   - Сразу после последней вкладки внутри прокручиваемого strip с обычным межвкладочным интервалом доступна кнопка «Новый чат» в виде простого плюса без отдельной рамки, когда полоса показана. Обычный клик открывает штатный экран нового чата с фокусом на поле ввода. Через 300 мс наведения мыши открывается плавное меню проектов с самой свежей активностью чатов (включая дочерние); архивные чаты и личный проект не участвуют. Меню располагается под плюсом и выравнивается по его левому краю, если хватает места; при нехватке места допускается сдвиг к центру экрана. Выбор проекта открывает тот же штатный экран с выбранным проектом. Кнопка списка вкладок также открывает своё меню через 300 мс наведения мыши, сохраняя обычное открытие по клику. Уход указателя до задержки отменяет открытие; навигация с клавиатуры открывает меню по ArrowDown. Изначально видны 15 последних активных проектов; «Ещё» догружает следующие 15 сразу по click/tap или через 300 мс наведения, пока доступные проекты не закончатся. Меню закрывается плавно; меню списка вкладок также плавно появляется и закрывается. В меню списка вкладок поле поиска нечетко фильтрует доступные закреплённые и исторические чаты по названию (без архивных/deleted tombstones), включая записи за пределами первых 8; ArrowUp/ArrowDown выбирают результат, Enter открывает чат. Два быстрых последовательных отпускания Shift в пределах 350 мс открывают меню и фокусируют поиск, когда полоса доступна; двойной Shift обрабатывается и при фокусе в поле ввода чата, после чего фокус переходит в поиск; фокус embedded BrowserView не перехватывается. При сниженной анимации ОС переходы отключены.
7. Активная вкладка имеет нейтрально-серую theme-derived заливку, неактивные — более светлую/фоновую.
8. Обычный клик — первичное действие любой вкладки: он открывает чат через `experimental_useSidebarThreadActions().open()`. Средний щелчок (нажатие колёсика) закрывает вкладку через тот же plugin-owned Close-путь и предотвращает browser autoscroll; другие auxiliary-кнопки не закрывают вкладку. Hover-подсказка и pointer-курсор на всём tab, включая название, сообщают именно об этом действии; inline-редактирование остаётся вторичным double-click жестом и не рекламируется в hover.
9. Контекстное меню открывается правым щелчком по вкладке и всегда содержит «Переименовать» (модальное окно), «Архивировать», «Скопировать ссылку» и «Пометить непрочитанным». Его desktop-поверхность повторяет compact contract native sidebar BB: `min-width: 7rem`, `p-1`, строки `px-2 py-[0.3125rem] text-xs`, иконки `1rem`, один разделитель перед архивированием и короткая theme-derived тень.
   - Для временной preview-вкладки оно показывает «Закрепить», для закреплённой — «Открепить». Эти пункты меняют только plugin-owned pin: откреплённая вкладка становится единственной preview и заменяет прежнюю preview согласно инварианту V1.
   - Inline-редактор и модальное окно используют один публичный `experimental_useSidebarThreadActions().rename()`; успешное имя также сохраняется в plugin-owned fallback-state.
   - «Архивировать» вызывает публичный `archive()` BB: он архивирует чат вместе с потомками и закрывает их native panes. Плагин слушает lifecycle-событие и удаляет соответствующие записи tabs/pin даже если archive/delete сделан вне его UI.
   - «Скопировать ссылку» записывает абсолютный URL текущего BB origin в clipboard; при запрете Clipboard API используется textarea fallback.
   - «Пометить непрочитанным» вызывает публичный `setRead(threadId, false)`; runtime-индикатор при этом не меняется.
10. Close через кнопку `X` или средний щелчок убирает только запись из верхней полосы и не архивирует/не останавливает чат. В BB Desktop `Ctrl+W` (на macOS также `⌘W`) для текущей plugin-вкладки синхронно подтверждается через `onCloseWindowRequest`, поэтому нативное закрытие окна не запускается. Исключение — текущий фокус нативного BrowserView либо его renderer-chrome: capability `browser.onFocus` и DOM-проверка не дают плагину обработать shortcut, так что штатный handler BB закрывает active browser tab. В web-клиенте `Ctrl+W` принадлежит браузеру и для закрытия вкладки используется её кнопка либо средний щелчок. При закрытии активной вкладки плагин открывает другую вкладку того же проекта, если она есть.
11. `Ctrl+Tab` открывает следующую, `Ctrl+Shift+Tab` — предыдущую plugin-вкладку в текущем горизонтальном порядке с циклическим переходом через край. Shortcut обрабатывается только при текущей plugin-вкладке и минимум двух вкладках; выбранная вкладка прокручивается в видимую область. Bare `Shift+Tab` не перехватывается и сохраняет стандартный обратный переход фокуса. Во время inline/modal rename или drag переключение не выполняется.
12. На root-экране «Новый чат» публичный `homepageSection` располагается непосредственно под штатным composer и показывает быстрый список закреплённых чатов.
   - Список содержит только закреплённые чаты в том же ручном порядке, что и основная полоса; preview в него не попадает.
   - Каждая сразу видимая карточка состоит из двух строк: название сверху; проект слева и статус справа во второй строке. Строка статуса появляется только при полезном сигнале: «Работает» для прямой либо вложенной работы и «Непрочитанное» при `isUnread`; спокойная карточка во второй строке показывает только проект, без точки и текста «Нет активности». Оба статуса могут отображаться одновременно. При нехватке ширины название проекта обрезается многоточием, а полное имя доступно в `title`.
   - Выбор карточки вызывает `experimental_useSidebarThreadActions().open(threadId)`. При отсутствии pin section даёт короткую подсказку, как закрепить первый чат.
   - Декларативная boolean-настройка `showPinnedTabsList` с label «Показывать закреплённые чаты на экране „Новый чат“» включена по умолчанию. При `false` section скрыт целиком, однако pin state, порядок и статусы вкладок остаются без изменений.
13. `showTabsOnDesktop` и `showTabsOnMobile` независимо управляют видимостью верхней полосы в существующих desktop и compact/mobile breakpoints. Отключённая поверхность не запускает собственные `tabs_list`/workflow revalidation; сохранённые pin/history state остаются доступными после повторного включения. `showTabListButton`, `showTabListPinned`, `showTabListHistory` и select `tabListButtonPosition` (`Слева`/`Справа`) меняют только presentation подменю: не удаляют state и не прекращают запись истории.

## Хранение и синхронизация

- Состояние V1 хранится в `bb.storage.kv` ключом `tabs.state.v1`.
- Сервер сериализует read–modify–write в одну очередь.
- При чтении прежнее V1-состояние с несколькими незакреплёнными записями нормализуется до последней preview-вкладки.
- После изменения сервер публикует `tabs-changed`; открытые окна используют его как invalidation/snapshot. Drag отправляет серверу намерение `source/target/position`, поэтому операция применяется к актуальному state даже при одновременной работе нескольких окон.
- Максимум 100 записей; при переполнении удаляются самые старые незакреплённые записи. Если KV уже повреждён и содержит более 100 одних pin, удаляются самые старые pin, чтобы восстановление не стало невозможным.

## Границы MVP

- UI регистрируется через публичный `homepageSection` и `experimental_appOverlay`; видимость root-списка задаётся декларативной настройкой `bb.settings.define`. Desktop capabilities `onCloseWindowRequest` и `browser.onFocus` запрашиваются только через feature detection и не требуют импорта или изменения BB core.
- CSS создаёт резерв в single-pane native chat: desktop с точным указателем использует полосу с proxy-scrollbar, а compact/mobile — touch-полосу с тем же icon-trigger подменю и горизонтальным свайпом. Одиночный native leaf открытой правой панели не считается split и не отменяет этот резерв: признаком split служит resize-boundary, который одновременно скрывает overlay.
- При открытой inline правой панели CSS anchor ограничивает overlay шириной main chat pane; в правой панели не появляется отступ и не перекрываются её native tabs. Если conversation свёрнута и правая панель заняла всю ширину, overlay скрыт.
- Нет content scripts, DOM-injection/reparenting, замены sidebar и изменения BB core.
- Нет записи в общий right-panel tab state (`threads.tabs.update`).

## Критерии приёмки

- Текущий чат появляется как preview и следующий новый чат заменяет только незакреплённую preview.
- Закреплённая вкладка переживает следующую активность и синхронизируется между окнами.
- Вкладка родителя получает рабочую точку, когда workflow выполняется в дочернем чате, включая durable workflow с временно нулевой sidebar activity; автоматический preview открывает родительский разговор, а не технический дочерний чат.
- Закреплённый tab перетаскивается в одну активную щель между любыми закреплёнными tab в единой горизонтальной линии, в том числе через границу проектов; выбранный порядок сохраняется после realtime-обновления. Preview не становится drag source или drop target, а сами tab не имеют отдельных левой/правой drop-зон. Hover любого tab показывает полные названия проекта и чата.
- Открытая вкладка с `isUnread: true` имеет отдельную видимую точку и доступное указание о непрочитанных сообщениях; рабочая точка при этом сохраняется независимой.
- На desktop переполненная полоса листается обычным колесом горизонтально, включая active tab, и показывает единственную нативную horizontal scrollbar над вкладками; при полном размещении вкладок rail отсутствует и полоса компактнее. Когда закреплённые вкладки и история вместе дают минимум два направления перехода, слева на desktop и compact/mobile есть одинаковый icon-trigger: меню сначала показывает закреплённые, затем recent history. Его вторая строка повторяет root-список: проект слева, короткий статус «Работает»/«Непрочитанное» справа; спокойный пункт не получает пустую точку. Первые 8 history-записей можно раскрыть следующими порциями через «Ещё»: click/tap сразу или удержание mouse pointer одну секунду на desktop; перед каждой новой порцией остаётся theme-derived разделитель. Архивированный/удалённый чат не остаётся в strip, pins или root-списке; его history tombstone disabled, зачёркнут и несёт Archive/Trash icon. Strip на compact/mobile справа листается горизонтальным touch-свайпом без proxy-scrollbar. `Ctrl/⌘+wheel` не меняется.
- Hover любой вкладки, включая её название, показывает primary click action и pointer-курсор; двойной щелчок по названию закреплённой вкладки даёт вторичное inline-переименование. Escape не сохраняет текст, включая последующий blur.
- Правый щелчок по вкладке открывает контекстное меню с точным набором действий: закреплением/откреплением по состоянию, переименованием в модальном окне, архивацией, копированием абсолютной ссылки и пометкой непрочитанным. Архивация выполняется штатным рекурсивным действием BB и удаляет запись из полосы.
- На root-экране «Новый чат» под composer виден быстрый список только pin в сохранённом ручном порядке; карточка выводит название сверху и проект слева во второй строке. Справа в той же строке появляется только «Работает» или «Непрочитанное»; у спокойного чата там нет индикатора. Узкий проект обрезается многоточием. Выбор открывает чат через host action. При `showPinnedTabsList: false` section отсутствует целиком, но tab state не меняется.
- Обычный click и Close (кнопка `X` либо средний щелчок), а также Desktop `Ctrl+W`/`⌘W` вне встроенного браузера, не меняют архивный статус и runtime чата; средний щелчок предотвращает browser autoscroll и не срабатывает от других auxiliary-кнопок. При фокусе BrowserView shortcut закрывает active browser tab и не удаляет plugin tab. В web-клиенте для chat tab используется кнопка Close либо средний щелчок.
- `Ctrl+Tab` и `Ctrl+Shift+Tab` циклически открывают следующую/предыдущую вкладку в текущем горизонтальном порядке и отменяют нативное событие только если реально переключили plugin tab. Bare `Shift+Tab` остаётся focus traversal.
- При открытой правой панели overlay не заходит в её область; compact/mobile single-pane поднимает root overlay над mobile page inset и резервирует ровно высоту touch-полосы. При открытом mobile sidebar/right-panel drawer либо split-pane overlay скрыт, поэтому не остаётся пустой верхний отступ timeline.
- `npm run typecheck`, `npm test` и `npm run build` завершаются успешно.
